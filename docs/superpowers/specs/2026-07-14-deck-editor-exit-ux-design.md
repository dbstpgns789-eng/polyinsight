# /deck 편집기 나가기 UX — 설계 (2026-07-14)

> 사용자 피드백: **"편집기에서 대시보드로 돌아가는 법을 몰라 헤맸다."**

## 1. 문제 진단

나가는 길은 **이미 있었다**. 못 찾은 게 아니라 **못 본** 것이다.

| 증상 | 코드 근거 |
|---|---|
| 탈출구가 본문과 같은 무게 | `DeckTopBar.tsx:62` — `‹대시보드`가 13px `text-ink-3`, 테두리·배경 없음. **클릭 가능하다는 신호가 형태에 없다** |
| 시선이 다른 곳으로 | 상단바에서 유일한 강조 = 초록 `내보내기`(`DeckTopBar.tsx:114`). 사용자는 "나가려면 내보내기를 눌러야 하나?"로 헤맨다 |
| 찾아도 벽이 하나 더 | 자동저장이 없어 `guardLeave`(`DeckTopBar.tsx:47`)가 *"나가면 사라집니다"* 다이얼로그를 띄운다 → **탈출이 위험한 행동으로 프레이밍** |

**근본 원인은 두 개다: ① 어포던스 부재 ② 나가기가 위험 행동.** 둘 다 고쳐야 한다 —
버튼만 크게 하면 다이얼로그 벽에 부딪히고, 다이얼로그만 없애면 여전히 안 보인다.

## 2. 선택한 방향 — A안 (문서 작업실)

Figma·Google Docs 모델. 덱은 **언제든 다시 돌아오는 문서**이고, 나가기는 **무서운 행동이 아니다.**

기각한 대안:
- **B안 (흐름의 한 단계, `저장하고 나가기` 버튼)** — 이름이 불안을 해소하지만 상단 강조 버튼이 3개가 되어
  **"1전압" 원칙**(강조는 하나)을 깬다.
- **C안 (A + 내보내기 완료 시 종료 모달)** — A의 상위집합. 지금은 A만 하고, export 완료 흐름은 별건으로 미룬다(YAGNI).

## 3. 설계

### 3-1. 상단바 배치

```
[← 대시보드]  [cellulose_2024] Fabrication…   ● 모든 변경 저장됨 · 14:32
                                    (spacer)
                (17/22 검증 · 5 검토)  [뷰어│편집]  [내보내기]  (계정)
```

| 요소 | 변경 |
|---|---|
| `← 대시보드` | **상단바 첫 요소**, 테두리 있는 버튼(`border`, `rounded-lg`, 13px `font-bold`). 좌상단 = F패턴 첫 시선 |
| 브랜드 로고 | **제거**. 이미 앱 내부라 브랜드 재확인은 불필요하고, 그 자리는 탈출구가 쓴다 |
| 저장 상태 | 파일명 옆에 상시 노출 — `● 모든 변경 저장됨 · hh:mm`. **"나가도 안전하다"를 형태로 증명** |
| 수동 `저장` 버튼 | **제거**. 상태 표시가 대체(실패 시에만 "다시 시도"로 부활) |
| `내보내기` | 유지 — **상단바의 유일한 강조**(1전압) |

### 3-2. 자동저장 (신규)

- **트리거**: 편집 후 **3초 유휴** 디바운스, `dirty`일 때만.
- **차단 조건** — 아래 상황엔 자동저장이 돌지 않는다:
  - AI 제안(`pending`)이 떠 있을 때 — 사용자가 수락/버림을 **결정 중**이다
  - 이미 저장 중(`saving`)
  - 드래그·리사이즈가 진행 중(에디터가 조작 중임을 알린다)
- **선택 보존**: 자동저장은 `setSelected(null)`을 **하지 않는다**.
  (현행 `handleSave`가 선택을 푼다 — 5초마다 선택이 풀리면 편집이 불가능해진다)
- **PNG 재렌더 억제**: 현행 `handleSave`는 `setVer(x+1)`로 뷰어 PNG를 다시 받는다.
  자동저장은 **편집 모드에서만** 돌고 편집 캔버스는 iframe(PNG 아님)이므로, `ver`를 올리지 않는다.
  **편집 → 뷰어 전환 시점에 한 번만** 올린다(그때 최신 PNG가 필요하다).
  안 그러면 3초마다 서버 렌더 7장이 헛돈다.
- **상태 머신**:
  ```
  clean ──(편집)──▶ dirty ──(3초 유휴)──▶ saving ──(성공)──▶ clean
                                            └──(실패)──▶ error ──(재시도)──▶ saving
  ```
- **실패 시**: `⚠ 저장 실패 — 다시 시도`(클릭 가능). **`dirty`가 남는 유일한 상태.**
- **이탈 직전 플러시**: `visibilitychange`(탭 숨김)·`beforeunload`에서 마지막 저장 시도(best-effort).

### 3-3. 나가기 다이얼로그

- **clean 상태 = 다이얼로그 없음.** 그냥 나간다.
- **error 상태에서만**: *"마지막 편집이 저장되지 않았어요. 나가면 사라집니다."* → `[취소] [그래도 나가기]`

## 4. 컴포넌트 경계

| 유닛 | 책임 | 의존 |
|---|---|---|
| `DeckTopBar.tsx` | 크롬 렌더 + 나가기 링크 + 저장 상태 표시. **상태를 만들지 않는다**(props만) | props |
| `useAutosave` (신규 훅, `web/src/lib/useAutosave.ts`) | 디바운스·차단조건·재시도·플러시. **UI를 모른다** | `patchDeck` |
| `deck/[jobId]/page.tsx` | 훅과 바를 배선. `handleSave`를 자동/수동 두 경로로 분기(선택 보존 여부) | 위 둘 |

`useAutosave(getHtml, { enabled, blocked, delayMs })` → `{ status, savedAt, retry, flush }`
`status: 'clean' | 'dirty' | 'saving' | 'error'`

## 5. 실패 처리

| 상황 | 처리 |
|---|---|
| 네트워크 실패 | `error` 상태. 자동 재시도 **1회**(3초 후), 그래도 실패면 사용자 재시도 버튼 |
| 서버 5xx | 동일 |
| 저장 중 사용자가 또 편집 | 큐잉하지 않는다 — 저장 완료 후 `dirty`면 디바운스가 다시 돈다 |
| 저장 중 나가기 클릭 | 저장 완료까지 기다리지 않는다. `flush()` 시도 후 이동(실패 시 다이얼로그) |

## 6. 테스트

**vitest (web)**
- `useAutosave`: 3초 유휴 후 1회만 호출 / 연속 편집 시 디바운스 / `blocked=true`면 미호출 /
  실패 시 `error` + 재시도 1회 / `flush()`가 즉시 호출
- `DeckTopBar`: clean일 때 나가기 클릭에 `confirm` 미호출 / error일 때만 호출

**수동(실브라우저)**
- 편집 → 3초 대기 → `● 모든 변경 저장됨` 뜨는지 → 새로고침 후 편집이 남아 있는지
- **선택 보존**: 요소 선택 → 3초 대기(자동저장) → 선택이 유지되는지
- AI 제안 떠 있는 동안 자동저장이 **안 도는지**

## 7. 완료 조건 (pass condition)

1. 편집 후 3초 유휴 → `저장됨` 표시 + 새로고침해도 편집 유지
2. 자동저장 중 **선택이 풀리지 않는다**
3. AI 제안 대기 중엔 자동저장이 **돌지 않는다**
4. clean 상태에서 `← 대시보드` 클릭 → **다이얼로그 없이** 이동
5. 저장 실패를 강제로 만들면(오프라인) → `⚠ 저장 실패` + 나가기 시에만 경고
6. vitest green, tsc green, 실브라우저 스크린샷으로 상단바 시각 확인

## 8. 범위 밖 (하지 않는다)

- 내보내기 완료 후 종료 모달(C안) — 별건
- 저장 이력/버전 목록 — 별건
- `/editor` (legacy 3패널) 는 손대지 않는다
