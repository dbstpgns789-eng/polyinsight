# Phase 0 — 반자동 발행 (SNS 게시 첫 계단) 설계 스펙

> 2026-07-21 · 상태: **초안 — 저쪽 세션 적대적 리뷰 대기 (R1)**
> 협업: 이 문서 = 두 세션 공유 계약. 리뷰 세션(프론트) ↔ 실행 세션(백엔드).

---

## 0. 왜 이걸 지금 (전략 앵커)

비전 = 유저가 논문→**검증된** 카드뉴스를 만들고 **자기 SNS에 발행**하는 워크플로우 제품(B). 근데 네이티브 원클릭 발행(Meta Graph API)은 **App Review + 사업자등록**이 필요 → 수 주 + 사업 결정. **Phase 0은 그 게이트를 전부 우회**해 B의 핵심 가치(검증 콘텐츠 → 발행)를 **며칠 만에** 준다.

- **하는 것**: 검증된 덱 → 인스타 게시용 캡션 생성 + 이미지·캡션을 30초 수동 게시 흐름으로 패키징
- **★얻는 것**: "유저가 실제로 발행하나?"라는 **외부 신호** — 우리가 그토록 못 구하던 것(저지 pause 9·save 0). 다운받아 올린다 = 발행급이다. 이 신호가 나중에 사업자등록·심사를 정당화한다.

---

## 1. 유저 잡 (Job-to-be-done)

> "검증된 카드뉴스 만들었다. 이제 **내 인스타에 올리고 싶다**."

현재: 유저가 ZIP export → 캡션 직접 고민 → 폰으로 이미지 옮김 → 인스타 열어 캐러셀 만듦 → 캡션 타이핑. **마찰 큼.**
Phase 0 후: "인스타에 올리기" → 캡션 생성돼 나옴(복사) + 이미지 다운 + 인스타 열림 → 붙여넣고 게시. **~1분.**

---

## 2. 스코프

### IN
- **캡션 생성기** — 덱 내용+출처 → 인스타 캡션(훅 + 평이 요약 + 출처 인용 + 해시태그)
- **IG-ready export UX** — 카드 PNG(이미 1080×1350 = 인스타 세로 규격, 리사이즈 불필요) + 캡션 → 다운/복사/열기

### OUT (명시적 — Phase 1+)
- Meta Graph API · OAuth · 원클릭 발행 (→ App Review + 사업자등록 필요)
- 예약·자동발행 (→ 워커 분리 L2)
- Threads·기타 플랫폼 (인스타 먼저; Threads는 다음)
- 성과분석 · 댓글/DM

## 3. 두 조각 + 계약

### 조각 A — 캡션 생성기 (실행 세션 · 백엔드/저작 도메인)
**신규 엔드포인트** (기존 캡션 인프라 없음 확인):
```
GET /api/deck/{jobId}/caption
  → 200 { "caption": string, "hashtags": string[] }
```
- 입력: `authored_deck`(html/paper_text) + 출처 메타(제목·저자·저널·DOI) + **verify_json(검증된 수치)**
- 캡션 구성: ①훅 1줄(덱 핵심 발견) ②2~3문장 평이 요약 ③출처 인용(논문 제목·저자·저널/DOI) ④해시태그
- LLM 호출(저작 도메인). 재생성 필요하면 `?regen=1` 또는 POST — 실행 세션 판단.

**★핵심 설계 제약 (fidelity — 설교 아니라 배관):**
캡션은 **공개로 나가는 새 텍스트**다. 캡션이 덱에 없는 수치를 지어내면 **가장 공개적인 순간에 "검증" 약속이 깨진다.** 그래서:
- 캡션의 수치는 **verify_json의 확인된 값에서만** 인용. 새 수치 발명 금지.
- 가능하면 캡션 수치도 V 파이프라인(`fidelity.verify_deck`류)으로 한 번 대조 — 미확인이면 캡션에서 제외.
- 이건 우리 니치 우위의 마지막 마일: Mirr 제네릭 캡션은 이 보증이 없다.

### 조각 B — IG-ready export UX (리뷰 세션 · 프론트)
export 모달(또는 뷰어)에 **"인스타에 올리기"** 액션:
1. 캡션 엔드포인트 fetch → **편집 가능한** 텍스트박스에 표시(유저가 최종 텍스트 소유) + **복사** 버튼(캡션+해시태그 합쳐 클립보드)
2. **이미지 다운로드** — 기존 배관 재사용: `POST /api/deck/{job_id}/export`(ZIP) 또는 카드별 `GET /api/cards/{job_id}/download/{n}`. 순서 카드1→N 보장
3. **인스타 열기** — `instagram.com`(또는 딥링크) 새 탭 (취향 포크 ③)
- 카드 PNG는 이미 1080×1350이라 **리사이즈 없음**. 순서만 확인.

### 계약면 (A↔B 인터페이스)
```
GET /api/deck/{jobId}/caption → { caption, hashtags }
```
이게 유일한 계약. 나머지는 각 세션 내부. **작아서 충돌 최소.**

## 4. 취향 포크 — ★세훈 확정 (2026-07-21)

1. **버튼** — **export 모달 안, 이름 "인스타 올리기"** (뷰어 별도 버튼 아님)
2. **캡션** — 세 가지 확정:
   - **톤 = 진지한 논문요약형** (SNS 훅형 아님 — 연구 니치 브랜드에 정합. 호들갑 금지)
   - **출처 = 간단하되 표기법 맞춘 짧은 인용** (전체 서지 아님. 예: `Ryu et al., Cellulose (2024)` 또는 짧은 DOI. 정식 표기법 준수 = 학술 신뢰 강화)
   - **해시태그 = 노출/도달 최적화** (연구 주제 태그 + 인기 태그, 개수 넉넉히)
3. **인스타 열기** — **자동으로 새 탭 열기** ("복사됨" 안내만 아님)

> ★캡션 결정(2)은 **조각 A(캡션 생성기, 실행 세션 소유)의 직접 입력**이다. 캡션 생성 프롬프트가 이 톤/출처/해시태그를 따라야 한다. **진지한 본문 + 도달용 해시태그** 조합은 모순 아님 — 본문은 신뢰·브랜드(연구 니치), 태그는 발견성. 두 층이 다른 일을 한다.

## 5. 완료 조건 (검증 가능 — 내 말 아님)

1. 완성된 덱을 가진 유저가: "인스타에 올리기" → 캡션 봄 → 복사 → 이미지 다운 → 인스타 열림 → 게시. **~1분 내.**
2. **캡션에 미확인 수치 0** — 캡션 수치가 verify_json 확인값과 일치(fidelity 배관).
3. **브라우저 E2E**: 실제 덱으로 흐름 끝까지 작동(리뷰 세션이 실렌더 검증).
4. 카드 순서 1→N 보존.

## 6. 소유 & 협업 루프

| 조각 | 소유 |
|---|---|
| `GET /caption` 엔드포인트 + LLM 캡션 + fidelity 대조 | **실행 세션(백엔드)** |
| export UX(버튼·캡션 표시/편집/복사·이미지 다운·인스타 열기) | **리뷰 세션(프론트)** |

**루프 (나에 대한 독립 견제 2겹):**
```

```

## 7. 리뷰 세션이 답해야 할 질문 (적대적 리뷰용)

1. `GET /caption` 계약이 맞나? 캡션 fidelity 대조를 verify 파이프라인 재사용으로 할 수 있나, 아니면 별도?
2. 이 작업이 지금 free-trial 배관·검증 하드닝과 **충돌**하나? (export 게이트: 무료는 export 잠금인데 "인스타에 올리기"도 export라 게이트 대상? — ★중요, 아래)
3. 캡션 생성 비용(LLM 1콜)이 덱 원가에 유의미한가?
4. 놓친 것?

**★열린 이슈 (리뷰에서 결론낼 것):** "인스타에 올리기"의 이미지 다운로드는 **export 경로**다. 무료체험 모델은 export를 결제 뒤로 잠근다(순수잠금). 그럼 Phase 0 발행도 유료 뒤인가? → **그렇다**(발행=export=가치벽). 캡션 **미리보기**까지는 무료(아하), 실제 다운로드·게시는 유료. 이 게이트 정합성을 실행 세션이 확인.
