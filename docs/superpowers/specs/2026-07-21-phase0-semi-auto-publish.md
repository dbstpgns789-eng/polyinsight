# Phase 0 — 반자동 발행 (SNS 게시 첫 계단) 설계 스펙

> 2026-07-21 · 상태: **R1 리뷰 완료 ✅ — R2 병렬 빌드 착수 가능**
> 협업: 이 문서 = 두 세션 공유 계약. 리뷰 세션(프론트) ↔ 실행 세션(백엔드).

---

## 0. 왜 이걸 지금 (전략 앵커)

비전 = 유저가 논문→**검증된** 카드뉴스를 만들고 **자기 SNS에 발행**하는 워크플로우 제품(B). 근데 네이티브 원클릭 발행(Meta Graph API)은 **App Review + 사업자등록**이 필요 → 수 주 + 사업 결정. **Phase 0은 그 게이트를 전부 우회**해 B의 핵심 가치(검증 콘텐츠 → 발행)를 **며칠 만에** 준다.

- **하는 것**: 검증된 덱 → 인스타 게시용 캡션 생성 + 이미지·캡션을 30초 수동 게시 흐름으로 패키징
- **★얻는 것**: "유저가 실제로 발행하나?"라는 **외부 신호** — 우리가 그토록 못 구하던 것(저지 pause 9·save 0). 다운받아 올린다 = 발행급이다. 이 신호가 나중에 사업자등록·심사를 정당화한다.

## 1. 유저 잡 (Job-to-be-done)

> "검증된 카드뉴스 만들었다. 이제 **내 인스타에 올리고 싶다**."

현재: 유저가 ZIP export → 캡션 직접 고민 → 폰으로 이미지 옮김 → 인스타 열어 캐러셀 만듦 → 캡션 타이핑. **마찰 큼.**
Phase 0 후: "인스타에 올리기" → 캡션 생성돼 나옴(복사) + 이미지 다운 + 인스타 열림 → 붙여넣고 게시. **~1분.**

## 2. 스코프

### IN
- **캡션 생성기** — 덱 내용+출처 → 인스타 캡션(훅 + 평이 요약 + 출처 인용 + 해시태그)
- **IG-ready export UX** — 카드 PNG(이미 1080×1350 = 인스타 세로 규격, 리사이즈 불필요) + 캡션 → 다운/복사/열기

### OUT (명시적 — Phase 1+)
- Meta Graph API · OAuth · 원클릭 발행 (→ App Review + 사업자등록 필요)
- 예약·자동발행 (→ 워커 분리 L2)
- Threads·기타 플랫폼 (인스타 먼저; Threads는 다음)
- 성과분석 · 댓글/DM

## 3. 두 조각 + 계약

### 조각 A — 캡션 생성기 (실행 세션 · 백엔드/저작 도메인)
> **R1 리뷰 반영 (실행 세션, 2026-07-21):** 초안의 "GET마다 LLM 호출"은 비용-DoS 구멍이었다. lazy+캐시로 재설계.

**신규 엔드포인트** (기존 캡션 인프라 없음 확인):
```
GET /api/deck/{jobId}/caption
  → 200 { "caption": string, "hashtags": string[] }
```
- **★lazy 생성 + 캐시** (게이트 아님): 첫 GET에서 생성해 `authored_deck`에 캐시 → **덱당 1회로 바운드**. 이후 GET은 캐시 read(LLM 0·무료·아하 유지). 캡션 미리보기는 무료여야 하므로 이 경로엔 export 게이트 **안 건다.**
- **regen = 유일한 비용 표면** → `?regen=1`에 **명시적 cap/rate-limit**(예: 덱당 N회 or 유저별 시간당). free-trial 원가방어를 캡션이 우회하지 않도록.
- 입력: **덱 HTML + verify_json(검증수치) + 출처 메타(제목·저자·저널·DOI)만.** ★**full paper_text(180k자) 재전송 절대 금지** — 그러면 입력토큰만 콜당 $0.5+, 원가 배증. 캡션은 작은 입력으로.
- 캡션 구성: ①훅 1줄(덱 핵심 발견) ②2~3문장 평이 요약 ③출처 인용(짧은 정식 표기) ④해시태그. 톤=진지 논문요약형(§4).
- **IG 제약 준수**: 캡션 max **2,200자** · 해시태그 max **30개**. 초과 시 인스타가 자름 → 생성기가 지켜야.

**★fidelity 규칙 (R1에서 더 엄격해짐 — 실행 세션 확정):**
초안은 "원문과 일치"였으나 **"덱의 검증된 수치 부분집합"**이 맞다. 이유: 덱이 이미 어떤 수치를 보여줄지 큐레이션했다. 캡션이 원문엔 있지만 **덱엔 없는** 수치를 인용하면 = 유저가 화면에서 안 본 걸 공개 발행하는 것.
- 실행 세션이 `fidelity.verified_number_strings(html, paper_text)`(검증 통과 수치 집합) 노출.
- 2단: ①프롬프트를 **검증된 수치로 제약** ②생성 후 `_MEASURE`로 캡션 수치 추출 → 검증집합에 없으면 **드롭**.
- 이건 우리 니치 우위의 마지막 마일: Mirr 제네릭 캡션엔 이 보증이 없다.

**★캐시 무효화 (R1 신규 발견):** 유저가 덱 편집(수치 변경)하면 캐시된 캡션이 낡는다("238 MPa 캡션 + 240으로 수정된 덱" 불일치). **편집(PATCH) 경로에서 caption 캐시 무효화** 필요.

### 조각 B — IG-ready export UX (리뷰 세션 · 프론트)
export 모달(또는 뷰어)에 **"인스타에 올리기"** 액션:
1. 캡션 엔드포인트 fetch → **편집 가능한** 텍스트박스에 표시(유저가 최종 텍스트 소유) + **복사** 버튼(캡션+해시태그 합쳐 클립보드)
2. **이미지 다운로드** — 기존 배관 재사용: `POST /api/deck/{job_id}/export`(ZIP) 또는 카드별 `GET /api/cards/{job_id}/download/{n}`. 순서 카드1→N 보장
3. **인스타 열기** — `instagram.com`(또는 딥링크) 새 탭 (취향 포크 ③)
- 카드 PNG는 이미 1080×1350이라 **리사이즈 없음**. 순서만 확인.

### 계약면 (A↔B 인터페이스)
```
GET /api/deck/{jobId}/caption → { caption, hashtags }
```
이게 유일한 계약. 나머지는 각 세션 내부. **작아서 충돌 최소.**

## 4. 취향 포크 — ★세훈 확정 (2026-07-21)

1. **버튼** — **export 모달 안, 이름 "인스타 올리기"** (뷰어 별도 버튼 아님)
2. **캡션** — 세 가지 확정:
   - **톤 = 진지한 논문요약형** (SNS 훅형 아님 — 연구 니치 브랜드에 정합. 호들갑 금지)
   - **출처 = 간단하되 표기법 맞춘 짧은 인용** (전체 서지 아님. 예: `Ryu et al., Cellulose (2024)` 또는 짧은 DOI. 정식 표기법 준수 = 학술 신뢰 강화)
   - **해시태그 = 노출/도달 최적화** (연구 주제 태그 + 인기 태그, 개수 넉넉히)
3. **인스타 열기** — **자동으로 새 탭 열기** ("복사됨" 안내만 아님)

> ★캡션 결정(2)은 **조각 A(캡션 생성기, 실행 세션 소유)의 직접 입력**이다. 캡션 생성 프롬프트가 이 톤/출처/해시태그를 따라야 한다. **진지한 본문 + 도달용 해시태그** 조합은 모순 아님 — 본문은 신뢰·브랜드(연구 니치), 태그는 발견성. 두 층이 다른 일을 한다.

## 5. 완료 조건 (검증 가능 — 내 말 아님)

1. 완성된 덱을 가진 유저가: "인스타에 올리기" → 캡션 봄 → 복사 → 이미지 다운 → 인스타 열림 → 게시. **~1분 내.**
2. **캡션에 미확인 수치 0** — 캡션 수치가 verify_json 확인값과 일치(fidelity 배관).
3. **브라우저 E2E**: 실제 덱으로 흐름 끝까지 작동(리뷰 세션이 실렌더 검증).
4. 카드 순서 1→N 보존.

## 7. R1 적대적 리뷰 — 결론 (실행 세션, 2026-07-21) ✅

방향·분담·계약면 승인. 실제 구멍 3개 + 놓친 것 3개 잡음:

1. **fidelity 재사용** — 가능. 단 규칙이 "원문일치"가 아니라 **"덱 검증집합 부분집합"**이어야(§3A 반영). `verified_number_strings` 노출.
2. **★게이트 정합성 (실행 세션 확정)** — 두 층으로 분리:
   - **(a) 이미지 다운로드** = `POST /export`·`GET /cards/../download/..` 둘 다 **이미 `plans.require_can_export` 걸림.** 무료 유저 다운 시 자동 402→페이월. "발행=export=유료" 맞고 **배관이 이미 강제** → **프론트 새 작업 0.**
   - **(b) 캡션 엔드포인트** = 게이트 걸면 안 됨(미리보기=아하=무료). 근데 "GET마다 LLM"이면 regen 연타로 **원가방어 우회 = 비용-DoS.** → **lazy+캐시**(덱당 1회 바운드), regen만 비용표면이라 거기 cap(§3A 반영).
3. **원가** — lazy+캐시면 +$0.03/덱(짧은 출력). **★단 full paper 재전송 금지**(콜당 $0.5+ 함정). 덱HTML+검증수치+메타만(§3A 반영).
4. **놓친 것 3개** → §3A 반영: ①캡션 staleness(편집 시 캐시 무효화) ②IG 제약(2,200자·30태그) ③regen 상한.

**착수 승인 지점**: (a) 다운로드=기존 게이트 재사용(리뷰 세션 작업 0) (b) 캡션=실행 세션이 lazy+캐시로 생성, 리뷰 세션은 **fetch만**. → **R2 병렬 빌드 가능.**

**배포**: 세훈 "한번에 몰아서" — 실행 세션 미배포분(검증오탐+OCR)에 캡션 얹어 한 번에. 캡션이 fidelity 재사용하니 정합적.
