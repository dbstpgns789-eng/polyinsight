# 팩트 체크 패널 — 수치 클릭 → 카드 위치로 점프 (설계)

> 2026-07-14 · 대상: `/deck/:jobId` 우측 팩트 패널(`DeckFactPanel`) + `core/fidelity.py`
> 상태: 설계 승인 대기

---

## 1. 문제

현재 팩트 패널은 **판독은 하는데 행동으로 이어지지 않는다.**

1. **막다른 골목.** "확인 필요 3건"과 원장을 보여주지만, 항목을 눌러도 아무 일이 없다.
   사용자는 "170% 증가가 원문에 없다"는 사실만 알고, **그게 어느 카드에 있는지 직접 찾아야 한다.**
   검증이 표면화까지만 가고 수정으로 연결되지 않으면 해자는 반쪽이다 —
   막지 않는 대신(헌법 §3) **고치기 쉽게** 해줘야 판단권이 실질이 된다.
2. **내부 용어 노출.** 헤더 `FIDELITY · 해자`, `CLAIM LEDGER`, `계산 불일치`는
   우리 팀의 사업/설계 언어지 사용자의 언어가 아니다. "해자"는 사용자에게 아무 의미가 없다.

## 2. 근본 제약 (이것이 설계를 결정한다)

`core/fidelity.py`의 `verify_deck()`은 **덱 HTML을 한 덩어리로 훑는다.**
따라서 claim에 **위치 정보가 없다** — 어느 카드에서 나온 수치인지 모른다.

반면 `derived_claims()`는 이미 `data-screen-label` 단위로 카드를 쪼개 검산한다.
**같은 분할을 V1에도 적용하면 카드 인덱스를 붙일 수 있다.** 이것이 이 작업의 심장이다.

## 3. 설계

### 3.1 백엔드 — claim에 `card` 필드 추가

- `verify_deck(html, paper_text)`을 카드 단위 루프로 재구성한다
  (`_CARD_SPLIT` 재사용 — `derived_claims()`와 동일한 분할).
- `NumberClaim`에 `card: int` 추가 (0-기반 카드 인덱스).
- `derived_claims()` 결과 dict에도 `card` 추가 (이미 카드 루프를 돌고 있으므로 인덱스만 기록).

**중복 수치 규칙(중요):** 현재 `seen` 집합이 같은 값을 덱 전체에서 한 번만 claim으로 잡는다.
카드로 쪼갠 뒤에도 **이 전역 dedup을 유지**하고, **첫 등장 카드**를 `card`로 기록한다.
그래야 원장 개수(`11 / 11`)와 상단 카운트가 지금과 동일하게 유지된다 —
이 작업은 검증 로직을 바꾸는 게 아니라 **위치를 덧붙이는** 작업이다.

**하위호환:** 기존 덱의 저장된 verify JSON에는 `card`가 없다.
프론트에서 `card == null`이면 클릭 비활성 + "위치 정보 없음 · 재생성하면 표시됩니다" 툴팁.
(재검증 경로를 타면 자연히 채워진다.)

### 3.2 프론트 — 클릭하면 그 카드의 그 수치로 데려간다

원장의 각 행을 `<button>`으로 바꾸고, 클릭 시 `{ card, value }`를 페이지로 올린다.

`/deck/[jobId]/page.tsx`:
1. 뷰 모드면 기존 `enterEditAt(card)`를 호출 — 편집 모드 + 해당 카드로 진입.
   편집 모드면 `editorRef.setPage(card)` + 드로어 닫기.
2. `EDITOR_READY`/페이지 이동 이후 editorAgent에 `HIGHLIGHT { value }` 전송.

**PNG 뷰어가 아니라 편집 모드(HTML)를 쓰는 이유:** 뷰어는 렌더된 PNG라 텍스트 위치를 알 수 없다.
편집 캔버스는 실제 DOM이라 텍스트를 찾아 좌표를 얻을 수 있다.

**자동 전환의 안전성(검증됨):** `toggleMode`의 PNG 버전 상승은 `pngStale` 가드를 탄다.
편집 모드에 들어갔다 아무것도 고치지 않고 나오면 재렌더도 `ver` 상승도 없다.
즉 "보러 들어갔다 나오기"는 부작용이 없다.

### 3.3 하이라이트 — DOM을 건드리지 않는다

editorAgent에 `HIGHLIGHT` 명령 추가:
- 현재 카드 안에서 텍스트 노드를 훑어 `value` 문자열을 찾는다.
- `Range.getClientRects()`로 좌표를 얻어 **기존 오버레이 레이어 위에 마커 박스를 그린다.**
- 카드 안에 같은 값이 여러 번 나오면 전부 칠하고, 첫 번째로 스크롤한다.
- 다른 곳을 클릭하거나 카드를 옮기면 마커는 사라진다.

**`<mark>` 태그 삽입 금지.** DOM을 바꾸면 문서가 dirty로 잡혀 **자동저장이 원본을 오염시킨다.**
하이라이트는 순수 오버레이여야 한다. (이 프로젝트는 이미 오버레이 기반 선택/드래그 기계를 갖고 있다.)

찾지 못하면(저작 후 편집으로 텍스트가 바뀐 경우) 카드 점프까지만 하고
"이 카드 안에서 찾지 못했어요 — 이미 수정하셨을 수 있어요"를 문맥 바에 표시한다.

### 3.4 문맥 바 — 확인 필요 항목을 순서대로 훑게 한다

편집 모드로 넘어가면 패널(드로어)이 닫혀 "무엇을 찾고 있었는지"를 잃는다.
캔버스 상단에 얇은 바를 띄운다:

```
170% 증가 — 원문에서 확인 안 됨          [다음 항목 →]  [닫기]
```

`다음 항목`은 확인 필요 목록의 다음 수치로 점프+하이라이트한다.
3건이면 3번 눌러 다 훑는다. 이것이 "표시만 하고 끝"을 "훑고 고친다"로 바꾸는 지점이다.

### 3.5 문구 — 내부 용어 제거

| 현재 | 변경 |
|---|---|
| `FIDELITY · 해자` (헤더 라벨) | **삭제** |
| `CLAIM LEDGER` | `수치 목록` |
| `계산 불일치` (배지) | `계산이 안 맞아요` |
| `원문에 없음` / `원문 확인` | 유지 (이미 평이함) |

## 4. 범위 밖 (YAGNI)

- 원문 PDF의 해당 위치로 보내기 (페이지/인용 좌표가 없다 — 별도 프로젝트)
- "괜찮음으로 표시"(무시) 상태 저장 — 아직 요청되지 않았다
- 뷰어 PNG 위 하이라이트 (좌표 파이프라인이 필요하고, 편집 모드로 충분하다)

## 5. 완료 조건 (pass condition)

1. `pytest backend/tests/` — `verify_deck`이 각 claim에 올바른 카드 인덱스를 붙인다
   (2장짜리 덱 픽스처: 카드0의 수치는 `card=0`, 카드1의 수치는 `card=1`).
   claim 개수·verified/unverified 카운트는 **변경 전과 동일**하다(회귀 방지).
2. `card` 없는 구 verify 데이터로도 패널이 깨지지 않는다(클릭 비활성).
3. 실브라우저: 확인 필요 항목 클릭 → 해당 카드로 이동 → 그 수치에 마커가 보인다(스크린샷).
4. 하이라이트 후 아무것도 고치지 않고 뷰로 돌아가면 `ver`가 오르지 않는다(PNG 재렌더 없음).
5. 화면 어디에도 `해자`·`FIDELITY`·`CLAIM LEDGER` 문자열이 없다.
