# V1 대조 계층 재설계 — substring → 수치 동등 비교

> 2026-07-20. 검증(V)은 이 제품의 해자다. 대조 방식을 바꾸는 건 해자의 심장을 바꾸는 일이라
> 스펙을 먼저 쓴다. 실측 근거: 덱 19개·claim 232건 전수 분석(①② 수정 후 미확인 8건).

## 1. 문제 — 원시연산 하나가 양방향 오류를 만든다

현재 V1(`fidelity.py`)의 대조는 한 줄이다:

```python
verified = core in paper_exp or core in paper_flat   # 정규화 없는 raw substring
```

이 방식은 **관대해야 할 곳에 엄격하고, 엄격해야 할 곳에 관대**하다.

**오탐(억울하게 잡음) — 실측 잔여 4건:**

| 카드 | 원문 | 원인 |
|---|---|---|
| `0.0001mm` | `100 nm` | 단위 환산 (같은 값) |
| `1.63` | `1.626 ± 0.16 μg` | 반올림 |
| `99.7%` ×2 | `0.32 wt%` | 파생(여집합 `100−0.32`) |

**미탐(근거 없는데 통과) — 구조적:**

카드가 `5배`라고 쓰면 core는 `"5"`. 논문 어딘가에 `5`는 **반드시** 있으므로 무조건 `VERIFIED`.
근거 없는 주장이 배지를 달고 나간다. **오탐보다 이쪽이 해자에 더 치명적이다.**

## 2. 설계 — 3층 분리

`문자열 포함` → `추출 → 정규화 → 수치 비교`

```
[원문] --추출--> PaperFact{value, dim, raw}  (1회, 캐시)
[카드] --추출--> Claim{value, dim, precision}
                        |
                     비교: 같은 dim 안에서 |v−p| <= tol(precision)
```

### 2-1. 추출 (extract)

원문·카드 양쪽에서 `(수치, 단위)` 쌍을 뽑는다. 이미 있는 `_NUM`/`_UNIT` 자산을 재사용하되,
원문 쪽에도 같은 추출기를 적용한다(현재는 원문을 통짜 문자열로만 씀).

파싱 대상:
- `1,750` → 1750 (콤마 제거)
- `3.64E+03` → 3640 (과학표기 네이티브 파싱, `_expand_scientific` 대체)
- `1.626 ± 0.16 μg/cm²` → value=1.626, unit=`μg/cm²` (±오차는 별도 보관, 비교엔 미사용)
- `175 billion` → 1.75e11 (영어 크기 어휘)
- `1,750억` → 1.75e11 (한국어 크기 어휘, 기존 `_KO_MAG` 승계)

### 2-2. 정규화 (normalize) — SI 접두어를 걷어내고 **차원**을 남긴다

| 차원 | 기준 단위 | 접두어 |
|---|---|---|
| 길이 | m | Å 1e-10 · nm 1e-9 · μm 1e-6 · mm 1e-3 · cm 1e-2 · km 1e3 |
| 질량 | g | pg · ng · μg · mg · kg |
| 부피 | L | μL · mL · dL |
| 압력 | Pa | kPa · MPa · GPa · bar(1e5) |
| 농도 | M | pM · nM · μM · mM · mol/mmol/μmol |
| 전압 | V | μV · mV · kV |
| 시간 | s | ns · μs · ms · min(60) · h(3600) |
| 주파수 | Hz | kHz · MHz |
| 분자량 | Da | kDa |
| 무차원 | — | % · ‰ · 배 · 점 · 개 · 층 · rpm · ℃ |

복합 단위(`μg/cm²`)는 **분자 접두어만 정규화**하고 나머지를 차원 태그로 유지한다
(`63.66 μg/cm²` → value 6.366e-5, dim `g/cm²`). 완전한 차원 대수는 과잉이다(YAGNI).

**★차원 대조가 핵심 방어선이다.** 질량 주장은 압력 수치와 절대 매칭되지 않는다 —
substring에는 없던 엄격함이다.

### 2-3. 비교 (compare) — 허용오차는 **카드의 표시 정밀도**가 정한다

임의의 tolerance 상수를 두지 않는다. 카드가 `1.63`이라 썼으면 소수 2자리로 표시한 것이므로
**`1.63`으로 반올림되는 모든 값**이 근거가 된다:

```
tol = 0.5 × 10^(-표시 소수자리)      # "1.63" → 0.005 → 근거 밴드 [1.625, 1.635)
```

- `1.63` ← 원문 `1.626` ✅ (밴드 안)
- `27.9` ← 원문 `27.88` ✅
- `1.63` ← 원문 `1.70` ❌ (정당하게 거부)

**원칙**: 관대함의 근거가 "적당히"가 아니라 **"유저가 화면에서 본 자릿수"**다. 방어 가능하다.

**★왜 이 정도 관대함이 옳은가 (2026-07-20 제품 판단)**:
카드뉴스는 논문의 **전사(轉寫)가 아니라 대중화 산출물**이다. 목적은 논문을 학술적으로 설명하는 게
아니라, 대중이 그 논문과 그 연구실의 연구에 **관심을 갖게** 하는 것이다. 그래서 `1.626 → 1.63`은
부실이 아니라 **올바른 레지스터**다. 검증기가 물어야 할 질문은
"원문과 글자가 같은가"가 아니라 **"원문에 충실한가"**다. 표시 정밀도 밴드는 이 질문에 정확히 답한다.

## 3. 파생 확장 (④) — 닫힌 연산 집합 + 같은 카드 제약

V2(`derived_claims`)가 현재 커버: `N% 증가` · `N배` · `N%p`.

**추가는 여집합 하나뿐이다** (2026-07-20 판단 — 초안의 합계·비율은 **보류**):

| 연산 | 예 | 판단 |
|---|---|---|
| **여집합** `100 − a` | `99.7% ← 100 − 0.32` | **구현** — 실측 사례 있음 |
| 합계 `a + b` | — | 보류 — 관측 사례 없음 |
| 비율 `a/b × 100` | — | 보류 — 관측 없음 + `pct_change`와 중복 |

**★왜 좁히나**: 연산이 하나 늘 때마다 "아무 숫자나 어떤 쌍에서 유도 가능"해져 **미탐이 곱으로 증가**한다.
관측된 사례가 없는 연산은 짓지 않는다(투기적 코드 금지). 실제 케이스가 나오면 그때 근거를 갖고 추가한다.

여집합에도 두 제약을 못박는다:

1. **같은 카드 안의 수치**로만 유도 (덱 전역 금지)
2. **표시 정밀도 안에서 정확히** 일치 (근사 남용 금지)

## 5. ★수용 기준 (acceptance)

실측 하네스(덱 19개·claim 232건)로 전후 비교한다.

**통과 조건:**

1. **오탐 4건 해소** — `0.0001mm` · `1.63` · `99.7%`×2 가 `VERIFIED`로 바뀐다
2. **★정탐 2건 유지** — 아래가 `VERIFIED`가 되면 **실패**(해자 붕괴 신호):
   - `10,000.` (꿀 점도 비유 — AI가 더한 값, 원문에 없음)
   - `63.66` (원문에 `20.847`·`24.163`·`18.467`뿐 — 실제 오류 가능)
3. **미탐 회귀 테스트 신설** — `5배` 주장이 원문의 무관한 `5`로 통과하면 실패
4. 기존 테스트 31개 green, 전체 스위트 green

**2번이 가장 중요하다.** 오탐을 0으로 만들려다 정탐을 죽이면 검증기가 아니라 도장 찍는 기계가 된다.

## 6. 리스크

| 리스크 | 완화 |
|---|---|
| **해자 약화(미탐 증가)** — 정규화가 관대해질수록 틀린 수치가 통과 | 차원 대조로 상쇄(substring보다 엄격) + 수용기준 2·3으로 게이트 |
| 기존 덱 `verify_json` 결과 변동 | 재검증은 사용자 트리거 시점에만. 저장된 값은 그대로 두고 다음 검증 때 갱신 |
| 원문 추출 품질 한계(⑥) | **이번 스코프 아님** — S1 문제. 별도 티켓 |
| 성능(원문 재파싱) | 원문 인덱스는 덱당 1회. 현 규모에서 무시 가능 |

## 7. 비스코프

- 원문 추출(S1) 품질 개선 — 별개 문제
- 표/그림 안 수치 복원 — S1 영역
- LLM 기반 의미 대조 — 결정론적 검증이라는 성격을 잃는다. 하지 않는다
- 완전한 차원 대수(dimensional algebra) — YAGNI
