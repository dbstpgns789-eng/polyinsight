# 결정 — JSON 씬그래프 전환 거절, HTML을 정본으로 유지

- **날짜**: 2026-07-26
- **상태**: 채택
- **범위**: 저작(S6) 출력 포맷 · 편집기 아키텍처 · DB 저장 표현
- **재현**: `web/harness/schema_probe.py`

## 제안된 것

외부 조언으로 다음이 들어왔다.

> HTML + iframe은 구조적 한계가 있다. iframe DOM 격리 때문에 postMessage 지옥이 되고,
> 통짜 HTML에서 개별 노드를 떼어내 드래그하는 것은 거의 불가능하며, AI 출력은 매번 달라
> 파싱할 수 없다. Canva·Gamma·Tome처럼 LLM이 JSON 씬그래프를 뱉고 프론트엔드가
> 렌더하는 방식으로 가라. Fabric.js / Konva.js를 쓰면 된다.

## 판정

**거절.** 단 조언 중 두 항목은 유효하며 별도로 채택한다(아래 "채택하는 것").

판단 근거는 논쟁이 아니라 실측이다. 두 덱(클로드디자인 셀룰로스 9장, 우리 test1 7장)을
제안된 스키마 `{id, type, x, y, width, style}`로 실제 인코딩해 바이트를 쟀다.

| | 클로드디자인 | 우리 |
|---|---|---|
| 리프 노드 | 313 (카드당 34.8) | 87 (카드당 12.4) |
| 배치 | flow 269 / absolute 44 | absolute 67 / flow 20 |
| SVG 내부 도형 | 53 | 56 |
| 노드당 스타일 선언 | 19.5 | 17.4 |
| 원본 HTML | 73,983 B | 37,141 B |
| 씬그래프 JSON(완전) | 221,897 B (**3.00배**) | 58,337 B (**1.57배**) |
| 제안된 예시 스키마 | 31,082 B (0.42배) | 11,163 B (0.30배) |

### 제안의 사실오류 3건

1. **"JSON이 가볍다"는 반대다.** 3.00배 / 1.57배로 무겁다. HTML은 CSS 캐스케이드로
   스타일을 공유하지만 씬그래프는 노드마다 최종값을 전부 든다(선언 6,113개가 펼쳐진다).
   예시 스키마가 0.42배로 가벼운 것은 그 6,113개 선언을 버렸기 때문이다.
2. **"PNG/PDF 출력에 JSON + Puppeteer가 수월"은 논리가 역전됐다.** Puppeteer와
   Playwright는 HTML을 입력으로 받는다. JSON이면 HTML로 되돌리는 렌더러가 추가로 필요하다.
   현재는 저작 산출물을 그대로 `backend/agents/deck/deck_renderer.py`에 넣는다.
3. **"undo는 JSON 스냅샷 배열 push"는 다운그레이드다.** 조작마다 문서 전체를 복사하면
   메모리가 선형으로 증가한다. 현재는 커맨드 패턴(do/undo 역연산)을 쓴다
   (`web/src/components/deck/editorAgent.ts:336-347`).

### 결정적 근거 — 형태 발명이 스키마를 깨뜨린다

SVG 내부 도형이 양쪽 모두 50개를 넘는다. FT-IR 스펙트럼의 `<path d="M… Q…">`를
`type` enum으로 담을 방법은 없다. 담으려면 `{type: "svg", raw: "<path …/>"}`가 되는데
그것은 JSON 안에 마크업을 넣은 것이다. 스타일도 실측 102개 속성이 필요하다
(논리속성 중복을 빼도 60개 안팎). 고정하면 61번째 속성이 필요한 날 마이그레이션이고,
열린 딕셔너리로 두면 CSS를 JSON으로 감싼 것이다.

즉 **형태 발명을 허용하는 순간 JSON은 마크업의 래퍼가 되고, 3배 무거워지며,
예측 가능성이라는 원래 이점이 증발한다.**

인용된 선례들의 공통점이 이를 뒷받침한다. Canva는 사람이 템플릿을 고르고 채운다.
Gamma는 슬라이드 레이아웃 패턴이 유한하다. **그들은 형태를 발명하지 않는다.**
헌법 §1은 형태 발명을 제품 정의로 두고 있다(`CLAUDE.md`). 도메인이 다르다.

### 제안이 옳았던 부분

- v2.0 카탈로그 폐기(헌법 §1)와 이 제안을 동일시하는 것은 부정확하다. v2.0이 실패한
  이유는 "30개 중 선택 강제 + architect/writer 분리"이지 JSON 표기법이 아니다.
- 한글 조판 손실은 Canvas 렌더(Fabric/Konva) 한정이다. react-rnd 같은 DOM 렌더라면
  조판은 유지된다.
- DB에 버전이 없다는 지적은 전적으로 옳다.

## 채택하는 것

**HTML을 저작·저장·렌더의 정본으로 두고, 노드 그래프는 편집 시점에 유도한다.**
이는 새 설계가 아니라 현행 구조의 명시화다.

- `freezeCard()` (`web/src/components/deck/editorAgent.ts:508-526`) 가 편집 진입 시
  카드 내 flow 요소를 절대배치로 일괄 승격한다. 제안이 "불가능"이라 한 노드 분리가
  여기서 해소된다.
- `collectLayers()` (`:854-875`) 가 DOM 트리에서 컨테이너를 버리고 리프만
  4종(text/image/graphic/shape)으로 뽑아 평평한 노드 목록을 만든다.

여기에 현재 없는 두 가지를 추가한다. 둘 다 훗날 JSON으로 전환하더라도 버려지지 않는다.

1. **revision 테이블** — 현재 `authored_deck`는 `job_id` PK UPSERT 덮어쓰기라
   이전 판이 소실된다(`backend/core/db.py:489-503`). AI 편집 되돌리기는 프론트
   `useState` 배열이라 새로고침 시 증발한다(`web/src/app/deck/[jobId]/page.tsx:153`).
2. **eid 기반 편집 스펙** — 전체 HTML 재출력을 끊는다.
   `docs/contracts/25_ai_designer.md`의 "최소 편집 스펙" 불변식과 같은 결론이다.

## 이 결정을 뒤집어야 할 조건

하나라도 참이 되면 재검토한다.

1. 형태 어휘를 유한하게 고정하기로 결정할 때(템플릿 제품으로 방향 전환, 헌법 §1 폐기)
2. 실시간 협업이 로드맵에 진입할 때(CRDT는 JSON 트리에 붙고 HTML 문자열에는 안 붙는다)
3. 렌더 타깃이 다변화될 때(PNG 외 비디오·인터랙티브)

2026-07-26 기준 셋 다 해당 없음.

## 부수 관찰 (미검증 가설)

배치 방식이 두 덱에서 갈렸다. 발행 판정에서 이긴 덱은 86%가 flow 레이아웃이고,
우리 덱은 77%가 absolute다. 절대배치는 논문마다 다른 텍스트 길이에 반응하지 못한다.
편집기 편의(freezeCard의 절대배치 승격)가 저작 단계의 취향까지 절대배치로
끌어당겼을 가능성이 있다. 검증 가치가 있으나 아직 측정하지 않았다.
