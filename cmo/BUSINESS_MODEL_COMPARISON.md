## 공통 전제 (세 안 모두 같음)

이건 이미 정해진 뼈대라 셋 다 공유한다:

- **무료체험** = 1덱 보기 전용. 생성·뷰어·편집·검증배지("✓ 수치 N건 원문 확인")까지 다 봄. **내보내기(export) 파일만 결제 뒤** (워터마크도 없는 순수잠금).
- **단위 = "덱" 하나.** 1 생성 = 1덱. 재생성도 1덱을 쓴다. (장수·논문 길이로 쪼개지 않는다 — 원가 편차가 좁아 정액으로 흡수)
- **원가** = 덱 1편 ≈ **₩1,400** (실측 올인, 편차 $0.9~1.2)
- **결제자 두 부류**: 개인 연구자(논문 억셉 때 몰아 씀·자비·가격 민감) vs 랩·기관(학생 여럿 상시·연구비·가격 둔감)
- **지금은 테스트 단계** → 적자 감수 OK(단 상한 방어). 품질·수요 증명되면 그때 가격 인상.
- **경쟁 앵커**: Mirra = $9 / $19 / $49 / $99 월정액(마케팅 풀스위트, fidelity 없음). 우리는 가격 경쟁 안 하고 **fidelity(수치 오류 0)로 연구 니치**를 잡는다.

세 안의 **차이는 딱 하나 — "덱을 어떻게 파느냐(청구 리듬)".**

## 두 페르소나 (시나리오용)

- **지훈 (박사생)** — 1년에 논문 3편. 억셉될 때마다 카드뉴스 5장씩 몰아 만든다. 자비 결제. 나머지 3~4개월은 아예 안 쓴다.
- **신소재랩 (김교수)** — 학생 6명, 매달 논문 2~3편 발행. 연구비로 결제. 상시 사용 + 학과 SNS도 운영.

## A안 — 충전제 (팩 구매 · 이월)

**정체:** 월 약정 없음. 덱 팩을 사서 쓴다. 안 쓴 덱은 **만료 없이 이월**.
예) 5덱 ₩15,000 · 15덱 ₩39,000 (덱당 ~₩3,000)

| | |
|---|---|
| 누구에게 | 버스티한 개인 연구자에 딱 |
| 장점 | 배관 단순(벽 뒤에 "팩 구매" 하나) · "논문 낼 때만 낸다" 정직함 · 이탈 없음 |
| 단점 | MRR 없음 · 매출 들쭉날쭉 · 예측 어려움 · LTV 낮음 |

**시나리오**
- 지훈: 논문 억셉 → 5덱 팩 ₩15,000 결제 → 5장 export. 안 쓰는 3개월은 0원, 남은 덱은 이월. → **편하다, 안 떠난다.**
- 랩: 매달 팩을 새로 사야 함 → 관리 번거로움 → 우리 입장에선 매출이 예측 안 됨.

---

## B안 — 구독제 (월 N덱 · 리셋)

**정체:** 월정액. 매달 N덱 충전, **안 쓰면 소멸**(리셋).
예) 개인 ₩19,000/월(10덱) · 랩 ₩69,000/월(30덱·시트 3) · 기관 문의

| | |
|---|---|
| 누구에게 | 상시 쓰는 랩·기관에 딱 |
| 장점 | MRR(예측 가능) · breakage 마진(안 쓴 덱=순이익) · 밸류에이션에 유리 |
| 단점 | 버스티 개인은 "이번 달 못 썼는데 소멸" → **해지** · 품질 증명 전 월 강제 = 환불 위험 |

**시나리오**
- 지훈: 월 ₩19,000 구독 → 논문 안 내는 달에 10덱 다 날림 → "돈 아깝다" → **해지.**
- 랩: 월 ₩69,000 → 매달 20~30덱 꾸준히 씀 → 딱 맞음 → **우리 MRR·예측 최고.**

---

## C안 — 하이브리드 (구독 베이스 + 이월 탑업)

**정체:** 둘 다 제공. 랩·기관은 월 구독, 개인·초과분은 이월 팩. (Mirra가 실제 쓰는 구조)

| | |
|---|---|
| 누구에게 | 두 부류 다 각자 자리 |
| 장점 | 랩에서 MRR + 개인에서 트랜잭션 = **매출 최대·저변 최대** |
| 단점 | 결제 배관 2개 · 유저에게 설명 복잡 · 만들 게 제일 많음 |

**시나리오**
- 지훈: 구독 안 하고 **탑업 팩만**(이월) → A안처럼 행동, 안 떠남.
- 랩: **구독 + 초과분 탑업** → B안처럼 MRR + 넘칠 때 유연.
- → 둘 다 만족. 대신 우리가 구독·팩 결제를 **둘 다** 붙여야 함.

---

## 한눈 비교

| | A · 충전 | B · 구독 | C · 하이브리드 |
|---|---|---|---|
| 청구 리듬 | 팩·이월 | 월·리셋 | 둘 다 |
| 개인(버스티) | ✅ 딱 맞음 | ❌ 이탈 | ✅ (팩으로) |
| 랩·기관 | ⚠️ 번거로움 | ✅ 딱 맞음 | ✅ (구독으로) |
| 우리 MRR | ❌ 없음 | ✅ 강함 | ✅ 강함 |
| 출시 난이도 | 🟢 제일 쉬움 | 🟡 보통 | 🔴 제일 복잡 |
| 테스트 단계 적합 | ✅ | ⚠️ | ⚠️(과설계) |

## 추천: **A안으로 시작 → 수요 신호 오면 C안으로 확장** (B 단독은 비추)

**지금(테스트 단계)은 A안.** 이유:
1. **배관이 가장 단순** — export 벽 뒤에 "팩 구매" 하나만 붙이면 됨. 세훈결정("배관 먼저, 데이터가 BM 결정")과 정확히 정합.
2. **개인 버스티에 정직** → 이탈 없이 저변 데이터를 모은다. 지금 필요한 건 매출이 아니라 "벽 부딪힌 사람이 사나?"라는 전환 데이터.
3. **품질이 아직 월 구독을 강제할 자격을 증명 못 함**(발행 save 0). 월 약정 강제는 품질이 값을 증명한 뒤.

**데이터가 쌓이면 C안으로 확장** — "랩이 매달 산다"는 신호가 보이면 그들에게 구독을 얹어 MRR을 만든다. 개인은 계속 팩.

**B안 단독은 비추** — 품질 증명 전 월 구독 강제 = 버스티 이탈 + 환불. B의 장점(랩 MRR)은 C안이 흡수한다.

> 한 줄: **A(지금) → C(수요 신호 후).** B는 C의 "랩 구독" 절반으로 살아남는다.

**공통 안전장치(어느 안이든):** 적자 감수는 하되 바닥 없는 적자는 금지 — Anthropic 월 스펜드캡 + 유저 하루 생성 캡(이미 있음). 그리고 "1덱 = 1생성"이라 재생성도 과금 → 원가 무한증식 차단.
